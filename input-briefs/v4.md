# V4 - Evolución de cupones

Marketing necesita poder modificar cupones que ya se encuentran en uso sin
crear un cupón nuevo ni perder su historial.

Se incorpora:

`PATCH /coupons/:code`

La actualización debe ser parcial.

Algunos cambios deben poder aplicarse inmediatamente y otros programarse para un
momento futuro mediante:

- `effectiveFrom`

También se incorporan las siguientes propiedades configurables:

- `active`
- `maxUsesPerUser`

Un mismo cupón puede acumular más de una modificación programada.

Los demás campos configurables mantienen los nombres utilizados por la API de
cupones existente.

La identidad y el historial del cupón deben conservarse.

Las reglas existentes de elegibilidad, descuento y utilización deben seguir
siendo compatibles con las modificaciones.
