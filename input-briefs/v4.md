# V4 - Evolución de cupones

Marketing necesita poder modificar cupones que ya se encuentran en uso sin crear
un cupón nuevo ni perder su historial.

Se incorpora:

`PATCH /coupons/:code`

La actualización es parcial.

Algunos cambios deben poder aplicarse inmediatamente y otros programarse para una
fecha futura mediante:

- `effectiveFrom`

También se incorporan como propiedades configurables:

- `active`
- `maxUsesPerUser`

Las actualizaciones deben soportar múltiples cambios programados sobre un mismo
cupón.

El resto de los campos configurables del cupón mantiene los nombres utilizados
por la API existente.

La identidad y el historial del cupón deben mantenerse a lo largo de su
evolución.

Las reglas existentes de elegibilidad, descuento y utilización deben seguir
siendo compatibles con este nuevo comportamiento.
